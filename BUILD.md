# Building the Ngaren Android app

This is an Expo SDK 56 app. `android/` is generated by `expo prebuild`, so all
native build configuration lives in `app.json` + `plugins/withAndroidBuildFixes.js`
(disables release lint, pins ABIs to `arm64-v8a,x86_64`).

## Modes

The app ships in two data modes, selected by env vars (`.env`):

- **Mock mode** (default — no `EXPO_PUBLIC_CERES_PLATFORM_URL`): all screens use
  `src/data/mock.ts`. Fully functional offline.
- **Live mode**: set `EXPO_PUBLIC_CERES_PLATFORM_URL` + `EXPO_PUBLIC_NGAREN_CONSUMER_ID`
  and the app hits the same platform-api endpoints as the Nuxt web app (1:1 parity).
  Supabase auth is independent and turns on with `EXPO_PUBLIC_SUPABASE_URL` +
  `EXPO_PUBLIC_SUPABASE_ANON_KEY`.

## Local release APK

Native release modules must currently be built **one ABI per Gradle invocation**
on Windows (see "Known issue" below):

```bash
cd android
# x86_64 (emulators, Chromebooks) — verified working
./gradlew :app:assembleRelease --no-daemon \
  -x lintVitalRelease -x lintVitalAnalyzeRelease \
  -PreactNativeArchitectures=x86_64

# arm64-v8a (physical phones)
./gradlew :app:assembleRelease --no-daemon \
  -x lintVitalRelease -x lintVitalAnalyzeRelease \
  -PreactNativeArchitectures=arm64-v8a
```

Output: `android/app/build/outputs/apk/release/app-release.apk`. It is signed with
the debug keystore (sideloadable for internal testing). Min Android 7.0 (API 24),
runs through Android 17 (API 37) — verified on an `android-37` emulator.

## Brand assets

`assets/images/ngaren-logo.png` is the canonical brand mark (transparent,
1024x1024) — used on the login screen and the splash hand-off. Every other
icon file is derived from it by `scripts/generate-brand-assets.py`: flattened
onto white for `icon.png`/`favicon.png`, inset to Android's adaptive-icon safe
zone (~62% diameter) for `android-icon-foreground.png` and
`android-icon-monochrome.png` (alpha-only silhouette for Android 13+ themed
icons), solid white for `android-icon-background.png`.

To update the brand mark, replace `assets/images/ngaren-logo.png` (or pass a
new source path as an argument) and regenerate:

```bash
python scripts/generate-brand-assets.py
npx expo prebuild --clean   # native android/ must pick up the new icons/splash
```

## Background sync

`src/services/backgroundSync.ts` registers a periodic `expo-background-task`
(`expo-task-manager` under the hood) that calls the same
`GET /api/sync/devices` the web app's "Sync Devices" button triggers, so device
telemetry stays fresh even when the app isn't open. No-ops in mock mode and on
web/simulators. Registered once in `_layout.tsx` on app start; unregistered on
sign-out (`src/services/auth.tsx`).

## Production / device builds — EAS (recommended)

The supported way to produce distributable arm64 / universal binaries is **EAS Build**
(builds on Linux cloud, immune to the local Windows native-build issue):

```bash
npm i -g eas-cli
eas login
eas build -p android --profile preview      # universal APK (sideload)
eas build -p android --profile production    # AAB for Play Store
```

Profiles are defined in `eas.json`. (Requires an Expo account; the first run
provisions a project id.)

## Known issue: local arm64 native build on Windows

`react-native-reanimated`'s arm64-v8a CMake step can fail with
`ninja: error: manifest 'build.ninja' still dirty after 100 tries`. This is a
ninja self-regeneration loop triggered by wall-clock instability on the build
host (ninja compares file mtimes; a backward clock jump mid-compile makes
`build.ninja` look perpetually stale). It is environmental, not an app defect —
x86_64 builds reliably.

Mitigations, in order of preference:
1. Build via **EAS** (above) — no local clock dependency.
2. Ensure the host clock is stable/NTP-synced, then retry the arm64 command.
3. Enable Windows long paths and retry (belt-and-braces; paths here are already
   under the 250-char limit so this is rarely the cause).
